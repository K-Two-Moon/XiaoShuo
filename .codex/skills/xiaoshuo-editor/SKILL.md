# 小说编辑工作流

## 工作范围

将仓库中的 `原文`、`大纲`、`大纲改写`、`摘要`、`新改写摘要`、`章节拆分` 和 `正文` 视为相互关联的创作资料。执行任务前先定位并读取相关文件，再决定修改范围。

## 执行规则

- 先读取与当前任务直接相关的目录和文件，避免仅凭文件名猜测内容。
- 修改前保留原有文件结构、命名方式和编码；除非用户明确要求，不覆盖原始素材。
- 处理章节时检查人物设定、时间线、叙事视角、地点和因果关系，避免与已有内容冲突。
- 大纲或摘要发生变化时，说明可能受影响的章节；只有用户要求时才同步修改正文。
- 续写正文时明确续写位置，读取相邻章节后再创作或修改。
- 输出或写回文件时使用中文，并将修改限制在用户指定的范围内。

## 常用任务

- 大纲设计：先查看现有大纲和摘要，再补充目标章节的冲突、转折、人物动机和结局。
- 章节拆分：将大纲或原文拆成可执行的章节目标、场景、冲突和收束点。
- 摘要改写：保留情节事实和人物关系，只调整压缩程度、结构或表达风格。
- 正文创作：明确续写位置，读取相邻章节后再创作或修改。
- 一致性检查：按人物、时间线、地点、道具和事件因果逐项核对，并指出证据所在文件。

如果需要稳定的自动化检查，再在该目录添加 `scripts/`；如果需要较长的设定资料，再添加 `references/`，并在本文件中明确何时读取它们。
